# 灵灵老师 V0.1 技术架构与选型说明

> 本文件把前面「技术中立」的业务规格，落到具体的工程实现上。
> 它定义：用什么技术栈、怎么分层、目录怎么放、大模型怎么接、密钥怎么护、怎么一条命令跑起来，
> 以及每一层分别实现前面哪份规格。**业务逻辑权威仍在前面四份规格，本文件只解决「用什么承载它们」。**
>
> 选型已锁定（依据已确认的约束：本地 agent 开发 / 团队能看懂能改一点 / 先 Web 不套壳 / 国内大模型真联网）。

---

## 0. 选型约束回顾（决策依据）

| 约束 | 取值 | 对架构的影响 |
|---|---|---|
| 开发方式 | 本地 agent（如 Claude Code） | 选主流栈，AI 写得顺；目录与脚本清晰 |
| 团队代码能力 | 能看懂、能改一点 | 结构要直观可读，避免冷门技术与重配置 |
| 桌面端硬性程度 | 先 Web，0.1 不套壳（见 §6 决策） | 纯本地 Web 应用，但架构「套壳友好」，预留升级路径 |
| 大模型 | 国内大模型，真联网调 | 必须有后端代理保管密钥；做可切换抽象层 |
| 多学生 | 预置多个学生画像供切换（非真鉴权） | 后端做到最薄，登录=选择预置学生 |

---

## 1. 技术栈总览（已锁定）

| 层 | 选型 | 为什么是它 |
|---|---|---|
| 前端框架 | **React + Vite** **+ TypeScript** | 最主流、AI 最熟、生态最大；Vite 启动快、配置少 |
| 样式 | **Tailwind CSS** | AI 写 UI 最顺手，类名即样式，团队改动直观 |
| 后端 | **Node.js + Express**（轻量） | 与前端同语言（JS），团队心智负担小；只做薄薄一层 |
| 数据库 | **SQLite 单文件** | 零配置、单文件、关系清晰，直接落地《数据模型规格》 |
| 大模型 | **国内大模型 API**，封装在可切换抽象层后 | 真联网调体现核心卖点；抽象层让换家只改一处 |
| 运行形态 | **本地全栈 Web 应用**，一条命令起，浏览器打开 | MVP 演示最省事、最稳、最不易翻车 |

## 2. 分层架构

```text
┌─────────────────────────────────────────────────────────┐
│  前端（React + Vite + Tailwind）  浏览器内运行             │
│  ├─ 学生学习主界面（承载真实学习互动）                    │
│  ├─ 系统观察面板（展示决策链路）                          │
│  ├─ 报告预览（教师/家长摘要）                             │
│  └─ 学生选择入口（多画像切换，非真登录）                  │
│        │  HTTP（本地）                                     │
└────────┼──────────────────────────────────────────────────┘
         ▼
┌─────────────────────────────────────────────────────────┐
│  后端（Node + Express）  本地服务，薄薄一层               │
│  ├─ API 路由：会话、事件、报告、学生列表                  │
│  ├─ 教学编排器（实现《决策规格》：状态判定→选策略→关怀/画图）│
│  ├─ 忆感模块（读写长期记忆，实现《数据模型》§5 读写契约）  │
│  ├─ 深图模块（判题、知识点/错因归因）                     │
│  ├─ 大模型抽象层（统一接口，代理国内模型，保管密钥）★     │
│  └─ 数据访问层（封装 SQLite 读写）                        │
│        │                          │                       │
└────────┼──────────────────────────┼───────────────────────┘
         ▼                          ▼
┌──────────────────┐      ┌──────────────────────────────┐
│  SQLite (lingling.db) │  │  国内大模型 API（真联网）      │
│  落地《数据模型》九表  │  │  情绪识别 + 教学回应两类调用   │
└──────────────────┘      └──────────────────────────────┘
```

**为什么需要后端这一层（不能纯前端）**：两条硬理由——① 大模型 API 密钥绝不能进前端（会被盗刷），必须由后端保管并代理；② 业务逻辑（编排器、状态识别、记忆读写）放后端才安全、可控、可被观察面板如实记录。前端只负责展示与交互。

## 3. 各层与上游规格的对接

| 后端模块 | 实现哪份规格 | 关键职责 |
|---|---|---|

| 忆感模块 | 《数据模型》§5.1 读取 / §5.3 写回 | 会话开始读画像与掌握度；结束写回 |
| 深图模块 | 《决策规格》§2 作答信号、错因归因 | 判题、标知识点、归错因 |

| 大模型抽象层 | 《人设规格》§3 情绪识别契约、§5 回应生成 | 两类调用的统一封装 |

| 预置数据初始化 | 《种子数据与演示脚本》 | 建库时灌入学生、画像、知识点、题库 |

## 4. 大模型抽象层（核心，单列）★

这是「国内大模型 + 可切换 + 真联网 + 可降级」的落点，也是保护密钥的关口。

### 4.1 设计目标

```text
- 业务代码只调用统一接口，不关心背后是哪家模型。
- 换模型（通义/文心/GLM/Kimi/豆包/DeepSeek 等）只改抽象层一个适配器，不动业务。
- 密钥只存在于后端环境变量，绝不下发前端。
- 提供「降级开关」：网络异常或演示需要时，可切到预录响应，保证演示不翻车。
```

### 4.2 统一接口（示意）

```text
llmClient.recognizeEmotion(input)  // 对应《人设规格》§3 情绪识别契约
   输入：本轮文本 + 规则层客观信号 + 历史摘要 + 近2~3轮摘要
   输出：{ state, confidence, evidence }（严格 JSON）

llmClient.generateResponse(input)  // 对应《人设规格》§5 教学回应生成
   输入：state + strategy[] + care_triggered + visual_aid + 题目/解法 + 学生表现
   输出：tutor_response 文本
```

### 4.3 配置与降级

```text
- 模型选择、API 地址、密钥：全部走后端环境变量（.env，不入库不入前端不进版本库）。
- LLM_MODE = live | mock 开关：
    live → 真联网调国内模型（演示主用）
    mock → 读预录响应（断网兜底 / 离线调试 / 防演示翻车）
- 超时阈值（情绪识别建议≤3s）与兜底见《人设规格》§3.6。
```

> **安全提醒**：密钥进 `.env` 并加入 `.gitignore`；提供 `.env.example` 占位文件供他人填。
> 这条要在给 AI 的开发任务里明确，否则 AI 容易把密钥硬编码进代码。

## 6. 关于「桌面端 / 套壳」的决策

**V0.1 决策：不套壳，做本地 Web 应用，浏览器全屏演示。**

理由：
- 套壳（Tauri / Electron）会引入构建、打包、跨平台调试等额外复杂度，对「能看懂能改一点」的团队是纯负担。
- 套壳对演示效果几乎无加分——评委看的是屏幕上的交互，不是它是否独立 .exe。
- 真联网调大模型的体验，Web 与套壳完全一致。

**但架构「套壳友好」**：业务逻辑全在标准 Web 技术内，将来若需原生桌面，套一层 Tauri（推荐，比 Electron 轻）即可，几乎不动业务代码。这条路径预留好，现在不浪费。

> 若演示场景要求「像个独立应用、不暴露浏览器地址栏」，折中方案：用浏览器全屏（F11）/ kiosk 模式即可达到，仍无需套壳。

## 7. 运行方式（目标体验）

```text
1. 安装依赖：一条命令（如 npm install，AI 会配好 workspace 一并装前后端）。
2. 配置：复制 .env.example 为 .env，填入国内大模型的 API 配置。
3. 初始化库：首次运行自动建表 + 灌种子数据（schema.sql + seed.js）。
4. 启动：一条命令同时起前后端（如 npm run dev）。
5. 演示：浏览器打开 localhost，进入学生选择页 → 选一个学生 → 开始演示。
```

## 8. V0.1 明确不做（控制复杂度）

呼应《主规格》§流程边界，技术上同样排除：

- 真实用户鉴权 / 注册 / 密码 / 找回（登录=选择预置学生）。
- 多租户 / 服务器部署 / 云数据库（就本地单机）。
- 原生桌面打包（套壳留待 0.1 验证后）。
- 复杂状态管理库、微服务、容器化等重型工程（MVP 不需要）。

## 9. 落地待补 / 待团队确认

- **具体哪家国内大模型**：抽象层已支持随时换，可先选一家试情绪识别效果，不满意再换（只改 `llmClient.ts`）。
- **画图实现库**：函数图/几何图用什么前端库（如 plotly / 自绘 SVG / 数学画图库），与《数据模型》§4.5 的 `visual_aid_spec` 结构一并定，建议开发到画图环节时再定，避免过早锁死。
- 这些都不阻塞开发启动——可边做边定。
