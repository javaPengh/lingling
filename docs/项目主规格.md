# 灵灵老师项目主规格

## 1. 项目一句话定义

灵灵老师是一款面向高中生的 AI 伴学应用，通过主动感知与主动关怀、永久记忆、启发式教学、幽默调节和画图辅助，帮助学生在遇到学习困难时持续学下去。

## 2. 当前项目阶段

当前阶段为 V0.1 MVP 演示原型。

> *产品长期面向中小学生，底层能力具有跨学段扩展性；V0.1 以高中数学错题复习作为验证场景，先证明“长期记忆 + 学习状态识别 + 教学编排”的核心闭环，再逐步扩展到小学数学、初中数学和其他学科。*

本阶段目标不是完成完整商业产品，而是完成一个可演示、可解释、可参赛包装的核心闭环，让评委、老师或潜在投资人清楚看到：

> 灵灵老师不是普通 AI 问答工具，而是能围绕学生学习过程形成结构化记忆、识别学习状态，并主动调整教学策略的 AI 伴学系统。

## 3. MVP 核心目标

V0.1 的目标不是做完整教育平台，而是在一个可演示的学习闭环中验证五大核心能力是否能协同工作。

五大核心能力包括：

1. 主动感知与主动关怀  
   系统能根据学生的学习行为、作答情况、对话表达和历史记录，识别其当前学习状态，并在学生困惑、挫败或疲惫时主动调整教学策略。

2. 永久记忆  
   系统能沉淀学生长期学习记录，包括知识点掌握度、历史错因、学习状态变化、有效教学策略和复习任务，而不是只保存聊天记录。

3. 启发式教学  
   系统不默认直接给答案，而是通过拆小步、追问、提示和苏格拉底式引导，帮助学生自己完成关键推理。

4. 幽默哲学引擎  
   系统能在学生挫败或紧张时，用轻度幽默、类比或生活化表达降低压力，但幽默必须服务教学，不独立喧宾夺主。

5. 画图功能  
   系统能在几何、函数、示意说明等需要视觉辅助的场景中生成或展示图形，用图形高亮、标注或示意来帮助学生理解问题。

V0.1 要验证的是：

> 当学生在学习任务中遇到困难时，灵灵老师能否基于长期记忆和当前状态，选择合适的教学策略，并把本次学习结果沉淀为后续复习和报告。



## 4. 核心闭环

V0.1 必须跑通以下主闭环：

```text
统一登录
-> 学生进入今日任务
-> 学生做题或输入问题
-> 教学编排器接收学习事件
-> 忆感模块读取长期记忆和当前学习状态
-> 深图模块分析题目、知识点、错因和解题路径
-> 教学编排器融合学生状态与知识路径
-> 灵灵老师输出个性化教学回应
-> 学生继续互动
-> 本次学习复盘
-> 更新学生画像和学习事件
-> 生成主动复习任务
-> 系统观察面板展示记忆读取、状态识别、策略切换和写回数据
-> 报告预览展示教师/家长可读的学习摘要与建议
```

其中，教学编排器是总控；忆感和深图都向教学编排器提供上下文，而不是互相硬塞。

## 6. V0.1 使用对象与界面构成

### 6.1 产品本质：三角色应用

灵灵老师是一个面向**学生、家长、老师**三种角色的学习应用。不同角色登录后进入各自不同的界面，看到与自己相关的内容：

- **学生**：进入学习界面，与灵灵进行真实学习互动。**产品主体，孩子是直接使用者。**
- **家长**：进入报告界面，了解自己孩子的学习情况、状态与进度。
- **老师**：进入老师界面，查看所带学生的学习情况、薄弱点与干预记录。

成熟形态包含真实的注册/登录。**V0.1 为简化 MVP，不做真实注册登录，改为预置账号 + 选择进入**——即提供一个登录入口（预置账号选择页），从预置的学生/家长/老师账号中选择一个进入对应角色界面。将来把"预置账号选择"替换为真实登录即可，上层界面无需改动。

> 命名说明：登录入口在 MVP 里是"预置账号选择"，**它是登录页的简化替身，不是"孩子在产品内选择自己"**。孩子真实使用时是直接登录自己、进入学习，没有"选学生"这一步。

### 6.2 登录入口（预置账号选择页 · MVP 简化版）

应用的总入口。MVP 不实现真实鉴权，列出预置账号供选择：

- 学生账号：小宇、小哲、小琳（三个性格迥异的学生，用于演示因材施教对比）。
- 家长账号：小宇的家长（登录后看小宇的报告）。
- 老师账号：带这三个学生的老师（登录后看三个学生的情况）。

选择某账号即"以该角色身份登录"，进入对应界面。

### 6.3 学生学习界面（产品心脏，给学生本人）

承载真实学习互动，是产品主体。要求沉浸、温暖、零干扰——孩子的界面里不出现"观察""报告"等与他无关的入口。

核心任务：

- 展示当前学习任务。
- 接收学生题目、答案、追问、困惑表达。
- 展示灵灵的启发式引导、画图辅助、幽默调节和主动关怀。
- 展示本次学习复盘。
- 展示系统生成的后续复习任务。

### 6.4 报告界面（给家长 / 老师，真实角色功能）

报告**不是给学生看的**，是家长和老师了解孩子学习情况的界面。它是真实的产品功能（面向真实的另一群使用者），不是"未来价值的预览"。

- **家长视角**：自己孩子的学习摘要、状态说明、完成情况、陪伴建议、后续计划。
- **老师视角**：所带学生的学习摘要、薄弱知识点、错因、干预记录、复习建议。

> V0.1 不实现完整的教师/家长后台（班级管理、批量操作、消息通知等），只实现"登录后查看所关联学生的报告"这一核心。

### 6.5 系统观察面板（系统透视窗，不属于任何角色）

观察面板**不是产品功能，不是任何角色的界面**。它是系统的"决策日志/调用链路透视窗"，用途是：开发调试 + 演示时向评委展示"系统内部如何决策"。真实用户（学生/家长/老师）永远不应看到它。

实现上，它应是**独立于角色登录之外、演示/调试时可唤出的视图**，而非与角色界面并列的页面。它展示：

- 系统读取了哪些历史记忆。
- 当前题目识别出哪些知识点和错因。
- 检测到哪些学习状态信号。
- 教学编排器为什么切换策略。
- 本次学习写回了哪些结构化数据。
- 是否生成了主动复习任务。

## 7. 产品形态与技术边界

V0.1 的主交付形态为本地全栈 Web 应用（浏览器演示）。

### 7.1 界面结构

```text
登录入口（预置账号选择，= 登录页 MVP 简化版）
   ├─ 学生账号 → 学生学习界面（产品主体，沉浸独立）
   ├─ 家长账号 → 报告界面 · 家长视角
   └─ 老师账号 → 报告界面 · 老师视角

系统观察面板 = 独立的系统决策透视窗，演示/调试时唤出，不属于任何角色
```

### 7.2 V0.1 明确不做（控制范围）

- 真实注册 / 登录 / 密码 / 找回（用预置账号选择替代）。
- 完整教师端 / 家长端后台（班级管理、批量操作、通知、家校沟通等）。
- 多账号关系的复杂管理（家长管多孩、老师管整班的增删改）——V0.1 用固定的预置关系。
- 支付、订阅。
- 全学段、全学科覆盖。

### 7.3 角色与数据的关系（供数据模型落地）

- 账号有三种角色：student / parent / teacher。
- 家长账号关联其孩子（V0.1：小宇的家长 → 小宇）。
- 老师账号关联所带学生（V0.1：老师 → 小宇、小哲、小琳）。
- 学生账号即对应一个 student 实体本人。
- 详见《数据模型规格》中新增的账号与关联设计。

## 8. 数据原则

灵灵老师不能退化成普通 AI 聊天网页。

每次学习都必须沉淀结构化数据，而不是只保存聊天记录。

V0.1 至少需要沉淀：

- 学生。
- 会话。
- 题目。
- 学生答案。
- 是否正确。
- 知识点。
- 错因。
- 学习状态。
- 教学策略。
- 是否触发主动关怀。
- 干预结果。
- 掌握度。
- 复习计划。

原始对话不是唯一资产，结构化学习事件和学生画像才是核心资产。

报告预览应展示结构化摘要、学习趋势和可操作建议。

## 9. V0.1 验收标准

V0.1 完成时，至少应满足以下标准：

- 能进入桌面端演示应用，并打开学生学习主界面。
- 学生能进入今日任务并开始一次数学错题学习会话。
- 系统能读取该学生的历史薄弱点或预置学习画像。
- 系统能分析当前题目的知识点和关键错因。
- 系统能识别至少三类学习状态：平稳、困惑、挫败。
- 系统能根据学习状态改变教学回应方式。
- 系统能进行启发式追问，而不是只输出完整答案。
- 系统能在挫败场景中触发主动关怀或轻度幽默调节。
- 系统能在需要时展示一次图形或示意图辅助能力。
- 系统能保存本次学习的错因、状态、教学策略、干预结果和掌握度。
- 系统能生成至少一个主动复习任务。
- 学生学习主界面能看到本次学习复盘或个人学习画像。
- 系统观察面板能展示历史记忆、当前状态识别、策略切换原因和写回数据。
- 报告预览能展示面向教师/家长的学习摘要、复习建议和陪伴建议。
