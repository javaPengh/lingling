# 灵灵老师 V0.1 教学编排器决策规格

> 本文件是整个产品的「大脑规格」。它把主规格里五大核心能力中最易被「假实现」的部分——
> **状态识别、策略切换、主动关怀触发、画图触发**——从软描述固化为**可执行、可解释、可复现的规则**。
>
> 教学编排器是总控（见《项目主规格.md》第 4 节）。本文件规定：给定「学生当前输入 + 作答情况 + 长期记忆」，
> 编排器应**如何判定状态、选择策略、是否关怀、是否画图，以及为什么**。
>
> 本文件产出的每一个决策，都必须落进《数据模型规格.md》的 `learning_event` 字段：
> `state` / `state_evidence` / `strategy` / `strategy_reason` / `care_triggered` / `visual_aid_used` / `error_cause`。
> **凡是这些字段，必须由本文件的规则真实产生，禁止写死、禁止套话、禁止用随机值充数。**

---

## 0. 阅读前提

- 本文件所有状态短码、策略短码、错因短码、画图类型短码，**严格沿用《数据模型规格.md》第 2 节枚举字典**，不另造。
- 本文件只定 V0.1 演示所需的规则；规则用「可读条件 + 动作 + 理由模板」表达，便于 AI 直译为代码，也便于人工核对。
- **状态识别以大模型为主裁判，规则层供证据 + 做安全网（详见 §3）**，这是 V0.1 的核心能力，演示主路径即跑大模型识别：
  - 大模型层负责**判断**：读懂语气、反讽、委婉、跨轮情绪滑坡，输出 state + 置信度 + 依据；
  - 规则层负责**算客观事实喂给大模型**（连错次数、回复趋势、历史状态等）**并对明显离谱的判定做安全网修正**；
  - 大模型不可用/超时时，规则层保守基线兜底，保证演示不中断。
  - 大模型的完整调用契约（提示词、输入打包、输出结构、校验阈值）由下游《灵灵人设与提示词规格》做透。
- 无论走哪一层，产出的 `state_evidence` 必须是**真实命中的信号 / 真实的判断依据**，禁止编造、禁止套话。

## 1. 编排器的输入与输出契约

### 1.1 每一轮交互，编排器接收（输入）

| 输入 | 来源 | 用途 |
|---|---|---|
| 学生本轮原文 `student_input` | 学生主界面 | 提取情绪信号、困惑信号、作答内容 |
| 本轮作答与判定 `student_answer` / `is_correct` | 深图模块判题 | 作答情况维度 |
| 本轮题目与知识点 `question` / `knowledge_point_ids` / 命中错因 | 深图模块 | 归因与画图判定 |
| 本会话历史轮次 | session 内的 learning_event 序列 | 计算「连续答错次数」「同一知识点受阻次数」「会话时长」 |
| 长期记忆 | 忆感模块（student_profile、student_knowledge） | 调节起始策略、关注薄弱点、复用有效策略 |

### 1.2 每一轮交互，编排器产出（输出，逐字段落入 learning_event）

| 输出字段 | 由本文件哪一节决定 |
|---|---|
| `state` + `state_evidence` | §3 状态识别规则 |
| `strategy`（数组） + `strategy_reason` | §4 核心决策表 + §5 启发式降级阶梯 |
| `care_triggered` | §6 主动关怀触发规则 |
| `visual_aid_used` | §7 画图触发规则 |
| `error_cause` + `error_detail` | 由深图模块归因，编排器透传（本文件不重复定义） |

> **铁律**：`state_evidence` 与 `strategy_reason` 不可为空、不可是「系统判断」「根据情况」之类套话。
> 它们必须能让系统观察面板把「为什么这么判、为什么这么做」讲清楚。

## 2. 三类信号（状态识别的原料）

状态识别基于三类信号，按可信度排序：**情绪信号 > 作答信号 > 行为信号**（情绪表达最直接，故优先级最高）。

### 2.1 情绪/语义信号（来自 student_input 文本）

| 信号代号 | 触发关键词/语义（示例，可扩展同义词库） | 指向状态 |
|---|---|---|
| `SIG_GIVEUP` | 「我不会」「不想做了」「算了」「放弃」「太难了」 | frustrated |
| `SIG_SELFDOUBT` | 「我是不是很笨」「我好差」「怎么又错」 | frustrated / anxious |
| `SIG_ANXIETY` | 「来不及」「会考吗」「考试」「考不好」「紧张」 | anxious |
| `SIG_TIRED` | 「好累」「不想想了」「困」「头晕」 | tired |
| `SIG_CONFUSED` | 「没懂」「为什么」「这步怎么来的」「看不明白」 | confused |
| `SIG_POSITIVE` | 「懂了」「原来如此」「我会了」「谢谢」 | stable |

### 2.2 作答信号（来自 is_correct 与历史）

| 信号代号 | 条件 | 指向状态 |
|---|---|---|
| `SIG_WRONG_1` | 本轮首次答错 | confused（疑似） |
| `SIG_WRONG_STREAK` | 同一知识点连续答错 ≥ 2 次 | frustrated |
| `SIG_CORRECT` | 本轮答对 | stable |

### 2.3 行为信号（来自会话元数据）

| 信号代号 | 条件（阈值可在选型后微调） | 指向状态 |
|---|---|---|
| `SIG_LONG_SESSION` | 本会话时长 > 25 分钟 或 轮次 > 12 | tired |
| `SIG_RETRY` | 同一题反复修改作答 ≥ 3 次 | confused |
| `SIG_SLOW` | 本轮作答耗时显著长于该生均值 | confused / tired |

> V0.1 演示中，行为信号若难以采集，可仅用情绪信号 + 作答信号驱动，但**已采集的信号必须如实写入 evidence**。

### 2.4 跨轮趋势信号（来自本会话多轮累积，抓「情绪滑坡」）

> 这类信号是「主动感知」的关键：学生**单看任何一轮都不报警，连起来看才显露出疲惫或放弃前兆**。
> 全部从本会话已有的 learning_event 序列计算得出，**不需要回啃原始对话**，符合「结构化数据为核心资产」的原则。

| 信号代号 | 条件（阈值可在选型后微调） | 指向状态 |
|---|---|---|
| `SIG_TREND_NEGATIVE` | 最近 3 轮内负面信号（放弃/自我否定/困惑）累计 ≥ 2 次 | frustrated（升级前兆） |
| `SIG_TREND_SHORTER` | 学生回复长度连续 ≥ 3 轮递减（如从完整句到「嗯」「哦」） | tired / frustrated |
| `SIG_TREND_PASSIVE` | 从「主动提问/尝试」转为「被动单字回复」≥ 2 轮 | tired / 疏离 |
| `SIG_TREND_STATE_DECLINE` | 本会话 state 序列持续走低（stable→confused→frustrated） | frustrated |

> 跨轮趋势信号即使本轮文本「看起来正常」也可触发，这正是它的价值——**在学生明说之前察觉**。
> 命中时 evidence 须写明趋势，例：「学生近 3 轮回复从整句缩短到单字 → 判断为疲惫/疏离」。

---

## 2.5 历史记忆信号（来自跨会话长期记忆，调节而非直接判定）

> 区别于 §2.4（本会话内趋势），这一类来自**忆感模块的跨会话结构化记忆**，体现「永久记忆影响当下」。
> 它一般不单独定状态，而是**加权调节**：让判定对负面状态更敏感、关怀更早介入。

| 信号代号 | 来源字段 | 调节作用 |
|---|---|---|
| `MEM_RECENT_NEGATIVE` | student_profile.recent_states 近期多为 frustrated/anxious | confused 时上调关注；提前触发关怀（见 §6 R-C5） |
| `MEM_WEAK_POINT` | student_knowledge 本题知识点 mastery < 60 | 该知识点出错时更快进入帮扶升级（不苛责） |
| `MEM_EFFECTIVE_STRATEGY` | student_profile.effective_strategies | 同等条件下优先复用对该生历史有效的策略 |

> 用的是沉淀好的结构化字段（recent_states 等），**不回放原始聊天记录**——既快又契合数据原则。跨会话的原文级深度语义分析留待 V0.2+。

## 3. 状态识别：大模型为主，规则层供证据 + 做安全网

> **定调（V0.1 核心能力，台面主角）**：情绪/状态识别**以大模型为主裁判**。
> 这是产品区别于普通刷题工具的命根子——用 AI 真正读懂学生的语气、反讽、委婉和跨轮的情绪变化，
> 不是关键词匹配能替代的。因此 0.1 演示主路径就跑大模型识别，不藏在「预留接口」里。

「大模型为主」**不等于「大模型一个人说了算」**。规则层不退场，而是从「抢着定状态」转为两项大模型干不好的辅助职责：

```text
┌─ 规则层（信号引擎）：不再主导定状态，只做两件事 ─────────────┐
│  职责一·证据供给：把客观事实算准后喂给大模型——              │
│     连错次数、同知识点受阻次数、回复长度趋势、会话时长、       │
│     历史 recent_states/掌握度（§2.1~§2.5 信号清单）。          │
│     （这些是计数与统计，大模型自己数不准，不该靠它数）         │
│  职责二·安全网：对大模型返回结果做一致性校验——               │
│     若大模型判定与强信号明显矛盾（如学生连说「我不行了」却判   │
│     stable），拦截并按规则层保守值修正，避免演示翻车。         │
└──────────────────────────────────────────────────────────────┘
                          ↓ 信号清单 + 本轮文本 + 最近2~3轮摘要 + 历史摘要
┌─ 大模型层（主裁判）：做最终情绪/状态判定 ────────────────────┐
│  读懂反讽、委婉、上下文累积、情绪滑坡等规则抓不到的语义；      │
│  输出：state（五类之一） + 置信度 + 判断依据（写入            │
│  state_evidence）。依据须引用规则层给的客观信号，做到可解释。  │
└──────────────────────────────────────────────────────────────┘
        兜底：大模型不可用 / 超时 → 暂用规则层保守基线，保证演示不中断。
```

> 为什么这样分：大模型负责**判断**（它强在语义理解），规则层负责**算事实 + 兜底**（它强在精确计数与稳定）。
> 二者不是二选一，也不是谁替代谁——规则层产出的客观信号正是喂给大模型的上下文，
> 呼应主规格「忆感/深图向编排器**提供上下文**，而非互相硬塞」。
>
> **本节只定「主从架构与职责边界」。大模型识别情绪的完整调用契约**——系统提示词怎么写、
> 输入如何打包、要求输出什么结构（state+置信度+依据）、安全网校验的具体规则、超时兜底的阈值——
> **由下游《灵灵人设与提示词规格》的「情绪识别调用契约」一节做透**，避免本文件与提示词工程职责重叠。

### 3.1 规则层基线 / 安全网判定（R-S1~R-S6）

下列规则有**双重身份**：① 大模型不可用时，作为兜底的「保守基线状态」；② 大模型可用时，作为安全网的「强信号校验线」——大模型判定若与这些强信号严重冲突，则触发 §3.1 末的修正。

按优先级**自上而下匹配，命中即记录信号**（趋势信号 §2.4、记忆信号 §2.5 一并纳入）：

```text
规则 R-S1（最高优先：明确放弃/自我否定）
  IF 命中 SIG_GIVEUP 或 SIG_SELFDOUBT
  THEN state = frustrated
  evidence 例：「学生说『我不会，算了』→ 识别为挫败」

规则 R-S2（焦虑优先于一般困惑）
  IF 命中 SIG_ANXIETY
  THEN state = anxious
  evidence 例：「学生提到『快考试了来不及』→ 识别为紧张」

规则 R-S3（连续受挫 / 负面趋势）
  IF SIG_WRONG_STREAK（同一知识点连错≥2） 或 SIG_TREND_NEGATIVE 或 SIG_TREND_STATE_DECLINE
  THEN state = frustrated
  evidence 例：「『二次函数最值』连续答错 2 次，且近 3 轮负面表达累积 → 识别为挫败」

规则 R-S4（疲惫，含趋势）
  IF 命中 SIG_TIRED 或 SIG_LONG_SESSION 或 SIG_TREND_SHORTER 或 SIG_TREND_PASSIVE
  THEN state = tired
  evidence 例：「会话已 28 分钟，且学生回复连续 3 轮变短 → 识别为疲惫」

规则 R-S5（困惑）
  IF 命中 SIG_CONFUSED 或 SIG_WRONG_1 或 SIG_RETRY
  THEN state = confused
  evidence 例：「学生问『这步怎么来的』且首次答错 → 识别为困惑」

规则 R-S6（平稳，兜底）
  IF 命中 SIG_CORRECT 或 SIG_POSITIVE，或无任何负面信号
  THEN state = stable
  evidence 例：「本轮答对、无负面表达 → 状态平稳」
```

**安全网校验（大模型为主时生效）**：取大模型判定为最终结果，但遇下列「强信号冲突」时，规则层修正为括号内的保守值，并在 evidence 注明「大模型判 X，但命中强信号 Y，按安全网修正为 Z」：

```text
冲突 A：命中 SIG_GIVEUP/SIG_SELFDOUBT，大模型却判 stable → 修正为 frustrated
冲突 B：命中 SIG_WRONG_STREAK（连错≥2），大模型却判 stable → 至少修正为 confused
冲突 C：命中 SIG_ANXIETY，大模型判 stable → 修正为 anxious
```

> 安全网只拦「明显矛盾」，不干预大模型在 confused/tired/frustrated 之间的细分判断——
> 那正是大模型语义理解该发挥的地方。校验阈值与更多冲突项，由《灵灵人设与提示词规格》补全。

### 3.2 历史记忆对状态判定的调节（「永久记忆影响当下」的落点）

长期记忆（§2.5 信号）**不单独定状态，而是调节判定的灵敏度**，让系统对一个「最近过得不顺」的孩子更早察觉、更早关怀。这是产品「永久记忆 + 主动感知」两个卖点的交汇点，**必须显式实现，不可省略**。

```text
调节 M-1（负面史 → 提高灵敏度）：
  IF MEM_RECENT_NEGATIVE（recent_states 近期多为 frustrated/anxious）
  THEN R-S5 命中的 confused 上调为「需关注的困惑」，并提前触发关怀（§6 R-C5）
  evidence 须注明：「结合历史——该生近期多次受挫，故对本次困惑提高关注」

调节 M-2（薄弱点 → 不苛责，快帮扶）：
  IF MEM_WEAK_POINT（本题知识点 mastery<60）
  THEN 出错时更快进入帮扶升级（§5），evidence 注明「该知识点本就薄弱」

调节 M-3（复用有效策略）：
  IF MEM_EFFECTIVE_STRATEGY 存在
  THEN 同等条件下，策略选择优先取该生历史有效策略（§4 之上的偏好）
```

> 这三条调节让「读取了历史记忆」在系统观察面板里**看得见、说得清**：
> 例如面板可展示「读取到该生近期状态[挫败,困惑]→ 本次对困惑提高敏感度 → 提前介入关怀」。

## 4. 核心决策表（状态 × 作答情况 → 策略）

这是编排器的主表。**横轴=学习状态，纵轴=本轮作答情况**，单元格给出：`策略组合` + `是否关怀` + `理由模板`。
策略短码见数据模型 §2.2。一格可含多个策略，按执行顺序排列。

### 4.1 主决策表

| 作答情况 ＼ 状态 | stable 平稳 | confused 困惑 | frustrated 挫败 | tired 疲惫 | anxious 紧张 |
|---|---|---|---|---|---|
| **答对** | `socratic`（追问「为什么这样做」巩固）；care=否 | `socratic`+`hint`（确认理解再小幅追问）；care=否 | `humor`+`socratic`（先肯定鼓励再巩固）；care=是 | `humor`（轻松收尾，建议休息）；care=是 | `care`+`socratic`（先安抚再确认）；care=是 |
| **首次答错** | `socratic`（引导自检哪一步）；care=否 | `hint`（给方向性提示，不给步骤）；care=否 | `care`+`small_step`（先共情再拆步）；care=是 | `small_step`+`humor`（拆步+降负担）；care=是 | `care`+`hint`（先降焦虑再提示）；care=是 |
| **连续答错≥2** | `hint`→`small_step`（升级帮扶）；care=否 | `small_step`（拆到最小粒度，一步一确认）；care=否 | `care`+`humor`+`small_step`（关怀+幽默+逐步带）；care=是 | `care`+`small_step`（放慢，建议稍后再战）；care=是 | `care`+`small_step`（强安抚+稳步推进）；care=是 |
| **纯提问/表达困惑（未作答）** | `socratic`（反问引导其表达卡点）；care=否 | `hint`+`socratic`（提示+追问定位卡点）；care=否 | `care`+`socratic`（先接住情绪再引导）；care=是 | `care`（先回应疲惫，建议短休）；care=是 | `care`+`socratic`（安抚+引导聚焦当前一步）；care=是 |
| **明确放弃/要答案** | `socratic`（先尝试再引导，不直接给）；care=否 | `small_step`（降难度让其够得着）；care=是 | `care`+`small_step`；多次无效后才 `direct_explain`；care=是 | `care`（允许暂停，不强推）；care=是 | `care`+`small_step`（拆到极小，重建信心）；care=是 |

### 4.2 决策表的两条说明

1. **`socratic` 是默认底色**：除非状态或作答情况要求升级帮扶，编排器优先用追问而非给答案，呼应主规格「不默认直接给答案」。
2. **`direct_explain` 是最后手段**：仅当 §5 降级阶梯走到底（多次启发无效）或学生在 frustrated 下明确放弃时，才允许直接讲解，且讲完要回到 `socratic` 让学生复述。

## 5. 启发式降级阶梯（同一知识点受阻时的帮扶升级）

决策表给的是「单轮」策略；当学生在**同一知识点/同一题**反复卡住，编排器按下面的阶梯**逐级加大帮扶**，每升一级都要在 `strategy_reason` 注明「第几次受阻，故升级」。

```text
第 1 次受阻：socratic   —— 反问：你觉得这一步该用什么？
      ↓ 仍不会
第 2 次受阻：hint       —— 给方向：这里要用到判别式，想想为什么
      ↓ 仍不会
第 3 次受阻：small_step —— 拆步：我们先只解决「列出方程」这一步
      ↓ 仍不会 / 明确放弃
第 4 次受阻：direct_explain（兜底）—— 直接讲这一步，讲完请学生复述
```

> 这条阶梯是「启发式教学」可解释的核心证据：观察面板可展示「学生在 kp_003 第 3 次受阻 → 策略由 hint 升级为 small_step」。
> 阶梯的「受阻次数」从本会话 learning_event 中按知识点实时统计，不可写死。

## 6. 主动关怀触发规则（care_triggered）

`care_triggered = 是` 不是凭感觉，而是命中以下任一条件，并在 `strategy_reason` 写明命中原因：

```text
规则 R-C1：状态为 frustrated 或 anxious  → 触发关怀
规则 R-C2：命中 SIG_GIVEUP 或 SIG_SELFDOUBT → 触发关怀（即使状态尚未升级）
规则 R-C3：同一知识点连续答错 ≥ 2 次     → 触发关怀
规则 R-C4：状态为 tired 且学生表达负面    → 触发关怀（建议短休）
规则 R-C5【记忆加权】：忆感显示该生近期 recent_states 多为负面，
         则 confused 也触发轻度关怀（降低升级到挫败的概率）
```

**关怀的形态**（落在 `tutor_response`，细节由后续《灵灵人设与提示词规格》定）：
- 先接情绪、再回到题（顺序不能反）。
- 关怀≠免做：关怀后仍要带着学生往前走（配 small_step / hint），不是单纯安慰了事。
- 幽默（`humor`）可作为关怀的载体，但**幽默服务降压，不喧宾夺主**，且在 anxious 状态下慎用重幽默（怕学生觉得不被认真对待）。

## 7. 画图触发规则（visual_aid_used）

`visual_aid_used` 取值见数据模型 §2.7。判定顺序：

```text
规则 R-V1：题目自带 question.visual_aid_type ≠ none
          AND（学生处于 confused，或在该题受阻 ≥ 2 次）
          → 调用该题预设的画图（visual_aid_used = 该类型）
          理由例：「学生卡在函数最值的几何意义 → 调出函数图像辅助」

规则 R-V2：学生明确请求「画一下/图」 → 按题目可支持的类型调用
规则 R-V3：纯计算类题、或学生已理解（stable 且答对）→ visual_aid_used = none
```

> V0.1 至少要让演示路径中**有一次真实画图调用**（验收第 9 条）。画图参数取自 `question.visual_aid_spec`。
> 画图是「辅助理解」，不是每轮都画；滥用画图与不画同样错。

## 8. 多规则冲突的消解顺序

当多条规则同时可命中，按固定优先级裁决（保证可复现）：

```text
1. 安全/情绪优先：只要命中关怀条件（§6），先保证 care 进入策略组合。
2. 状态优先级：frustrated/anxious > tired > confused > stable（高优先状态主导策略选择）。
3. 帮扶就高不就低：降级阶梯（§5）算出的帮扶等级，与决策表（§4）给的策略取「更强帮扶」的一方。
4. 画图独立判定：§7 与策略选择并行，不互相覆盖。
```

每次裁决的依据要浓缩进 `strategy_reason`，例：
> 「状态=挫败(连错2次) + 同知识点第3次受阻 → 关怀优先，帮扶取 small_step（高于决策表的 hint）」

## 9. 一轮决策的完整执行流程（伪流程，供 AI 直译）

```text
输入：student_input, is_correct, question, knowledge_point_ids, 会话历史, 长期记忆

1. 提取信号（§2）：扫描情绪/作答/行为/**跨轮趋势/历史记忆**五类信号，记录命中清单。
2. 判定状态（§3，大模型为主）：规则层先算客观信号清单（连错次数、回复趋势、历史 recent_states 等）→ 连同本轮文本+最近2~3轮摘要交大模型做最终判定（输出 state+置信度+依据）→ 规则层安全网校验强信号冲突并按需修正 → 记忆信号按 M-1..M-3 调节。最终 state 与依据写入 state_evidence。大模型不可用/超时则暂用规则层保守基线。
3. 计算受阻等级（§5）：按知识点统计本会话受阻次数，得出降级阶梯等级。
4. 查决策表（§4）：用 (state × 作答情况) 取基础策略组合。
5. 关怀判定（§6）：命中任一 R-C → care_triggered = true，care 入策略。
6. 画图判定（§7）：按 R-V1..R-V3 定 visual_aid_used。
7. 冲突消解（§8）：合并 4/5 的策略，帮扶就高，去重排序，得最终 strategy[]。
8. 写理由：把 2/3/5/8 的关键判断浓缩成 strategy_reason（人话、可展示）。
9. 交给灵灵生成 tutor_response（依《灵灵人设与提示词规格》），连同上述字段写入 learning_event。
```

## 10. 一个完整示例（贯穿全表，供 AI 对照与自测）

**场景**：学生做「二次函数 f(x)=x²−2ax+1 在 [0,2] 上的最小值」这道含参题（知识点 kp_003 二次函数最值、kp_007 含参讨论）。忆感显示该生 kp_003 掌握度 52（薄弱），recent_states=["confused","frustrated"]。

| 轮次 | 学生输入 | 信号 | state + evidence | 受阻 | strategy + reason | care | 画图 |
|---|---|---|---|---|---|---|---|
| 1 | 直接答「最小值=1」（错，没讨论对称轴位置） | SIG_WRONG_1 | confused：首次答错且涉及薄弱点 kp_003 | 第1次 | `socratic`：引导其检查「a 在不在区间内」 | 否 | none |
| 2 | 「啊？还要分情况吗，没懂」 | SIG_CONFUSED | confused：明确表示没懂 | 第2次 | `hint`：提示「对称轴 x=a 可能在区间左/中/右」 | 否 | 触发 R-V1：调 function_graph 展示对称轴随 a 移动 |
| 3 | 「我不会，太难了」 | SIG_GIVEUP | frustrated（R-S1）：学生说我不会 | 第3次 | `care`+`humor`+`small_step`：先接住情绪→轻松类比→只解决「a<0 时」这一种情况 | **是**（R-C2、R-C3、记忆加权 R-C5） | annotation：在图上高亮当前讨论的区间段 |
| 4 | 跟着做对了 a<0 的情况 | SIG_CORRECT | stable：本步答对 | — | `socratic`：「那 a>2 时图像在区间哪边？同样的方法你来」 | 否 | none |

→ 复盘写回：kp_003 mastery 52→48（本次净受挫，微降）；recent_states 追加 frustrated；生成 review_task（reason：「含参二次函数最值连续受阻，需专项复习分类讨论」，附推荐题）。
→ 观察面板可逐轮展示「信号→状态→策略升级→关怀触发→画图」的完整决策链。
