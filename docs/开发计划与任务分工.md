# 灵灵老师 V0.1 开发计划与任务分工

---

## 0. 团队与节奏

**分工大原则**：

- **彭海守「核心链路」**：数据模型、编排器、状态识别、记忆读写、大模型对接、**以及对外的 API 接口定义**。这几样是产品命根子。
- **葛泽桐负责前端 + 数据 + 测试 + 文档**：四个页面（含学习主界面的展示）、画图组件、UI 打磨、种子数据录入与校验、自测脚本、README/操作说明。
- **关键前提**：先建好 §1.5的「风险隔离机制」

---

## 1. 开工前的一次性准备（半天，彭海来）

1. 建空仓库（Git），把六份规格放进 `/docs`，写一个最简 README 索引。
2. 用本地 agent（Claude Code）初始化项目骨架：React+Vite（/web）、Node+Express（/server）、SQLite，按《技术架构》§5 目录结构。
3. 跑通「空壳启动」：一条命令能起前后端、浏览器能打开一个空白页。**此步通过=环境就绪。**
4. 建一个共享的「待定决策清单」（见 §6），开发中撞到先挂着、就地拍板。
5. 这一步彭海做完葛泽桐再投入。

---

## 1.5 风险隔离★

**第一层 · 物理隔离**

- 代码分地盘：葛泽桐只在前端 `/web` 干活；彭海在后端 `/server` 和核心模块。
- 前后端只通过**彭海定义的 API 接口**通信。
- **Git 分支**：葛泽桐在自己的分支（如 `feature/xxx`）做。

**第二层 · 只读边界**
葛泽桐对以下文件**只能读、不能改**，需要改只能提给彭海：

- `/server/db/schema.sql`（建表）
- `/server/modules/`（orchestrator / memory / analyzer / llmClient 全部）
- API 接口定义文件（彭海统一维护）
- `/docs/` 下的规格文档（按它做，做的过程中如发现文档有问题就拿出来给彭海审核）

**第三层 · 契约先行（用 TypeScript 兜底）**
- 彭海把前后端之间传的数据结构先用 **TS 类型/接口定义好**（如「一轮交互的请求/响应长什么样」），放在一个共享类型文件里。

**第四层 · 任务可验证**
- 每个任务卡都带「完成标准」，葛泽桐自己先对照自测、跑得起来再交。
- 彭海验收只看「标准达没达到」，不必逐行读他的代码。不达标退回（退回的只是他的分支，主干安全）。

## 2. 四阶段总览

| 阶段 | 主题 | 大致天数 | 彭海 | 葛泽桐 | 阶段验收（跑给自己看） |
|---|---|---|---|---|---|
| 一 | 地基 | ~4 天 | 后端架子+建库+大模型抽象层(mock) | 种子数据录入+学生选择页 | 能选学生进入一个主界面雏形 |

## 3. 阶段一 · 地基（约 4 天）

**目标**：项目能跑、库建好、种子数据进去、能选学生进主界面雏形、大模型抽象层先用 mock 占位。

### 任务卡

**T1-1（彭海）建库 + 数据访问层**
- 做什么：按《数据模型规格》写 `schema.sql` 建九张表；写 `dao.js` 封装基本读写。
- 完成标准：能建库成功、能对每张表做增查；外键关系正确。
- 验收：跑一段测试脚本，插一条 student 再查出来，无报错。

**T1-2（彭海）后端架子 + 大模型抽象层(mock)**
- 做什么：Express 入口、基础路由骨架；`llmClient.js` 按《技术架构》§4 写统一接口，先实现 `mock` 模式（返回预录的假状态/假回应）。
- 完成标准：`recognizeEmotion` / `generateResponse` 在 mock 模式能返回结构正确的假数据。
- 验收：调一次返回合法 JSON，字段齐（state/confidence/evidence、tutor_response）。

**T1-3（葛泽桐）种子数据录入 + seed 脚本**
- 做什么：把《种子数据与演示脚本》§1~§3 的知识点、3 个学生、画像、掌握度、7 道题，写成 `seed.js`，首次运行灌库。
- 完成标准：库里能查到 3 个学生、9 个知识点、7 道题，字段与文档一致。
- 验收：彭海跑一句查询，三个学生画像、七道题都在（这正好也解决了之前「只看到一个学生」的担心——以数据库为准）。
- 难度：边界清晰，适合起步练手；做的过程中会熟悉数据结构。

**T1-4（葛泽桐）学生选择页 StudentPicker**
- 做什么：一个选择页，列出 3 个学生（名字+人设标签如「易放弃型」），点击进入。类似选用户头像。
- 完成标准：从后端拉学生列表渲染出来，点击能跳到主界面（主界面此时可为空壳）。
- 验收：页面能看到小宇/小琳/小哲三张卡，点击有反应。
- 依赖：T1-3 的数据、T1-1 的查询接口。

**阶段一并行说明**：T1-1/T1-2 彭海做，T1-3/T1-4 葛泽桐做；葛泽桐的 T1-4 依赖彭海先给「列出学生」的接口，所以彭海优先把那个接口先出。

## 4. 阶段二 · 核心闭环（约 6 天，重头戏）

**目标**：用 mock 大模型，把「学生输入→状态识别→选策略→灵灵回应→写回长期记忆→生成复习任务」整条主链路跑通。这是产品灵魂，彭海主导。

### 任务卡

**T2-1（彭海）深图模块 analyzer**
- 做什么：判题（对错）、标知识点、按《决策规格》§2.3 归错因。
- 完成标准：给一道题和学生答案，能返回 is_correct、命中知识点、错因分类。

**T2-2（彭海）状态识别（走 mock 大模型）+ 规则层信号**
- 做什么：实现《决策规格》§2 的信号计算（连错次数、跨轮趋势等）+ §3 的「规则层产证据 + 大模型裁决」架构；大模型这步先调 mock。
- 完成标准：给一轮输入，能产出 state + state_evidence，且 evidence 是真实命中的信号。
- 注意：这是「大模型为主」的落点，先把架构搭对，真模型阶段四再换。

**T2-3（彭海）教学编排器 orchestrator**
- 做什么：实现《决策规格》§4 决策表、§5 降级阶梯、§6 关怀触发、§7 画图判定、§8 冲突消解。
- 完成标准：给定 state+作答情况+历史，能产出 strategy[]、care_triggered、visual_aid_used，并写出 strategy_reason。
- 验收：照《决策规格》§10 那个含参二次函数示例走一遍，每轮输出与示例对得上。

**T2-4（彭海）忆感模块 memory + 写回**
- 做什么：实现《数据模型》§5 读写契约——会话开始读画像/掌握度，每轮写 learning_event，会话结束更新掌握度/画像、生成 review_task。
- 完成标准：一次会话结束后，掌握度有变化、画像 recent_states 有追加、生成了至少一条复习任务。

**T2-5（葛泽桐主做，彭海只提供接口+类型）学习主界面 Learning**
- 做什么：对话区（学生输入、灵灵回应）、当前题目展示、画图位、本次复盘展示——**整个前端页面葛泽桐负责**。
- 彭海只做：定义这个页面要调的 API 接口 + 对应 TS 类型，交给葛泽桐。之后不碰前端。
- 完成标准：能输入、能看到灵灵回应、能看到画图位、会话结束能看到复盘；调接口的数据类型与彭海给的一致（类型不报错）。
- 隔离保障：葛泽桐在自己分支做；做崩了不影响彭海后端。

**T2-6（葛泽桐）画图组件**
- 做什么：函数图先用成熟库实时渲染（按 visual_aid_spec 参数）；几何图（如正方体）**先用预置 SVG 占位**（见 §6 待定项，别在几何渲染上空耗）。
- 完成标准：q_001 的函数图能根据参数画出来、能高亮区间；q_006 几何图能显示一张占位示意。

**阶段二验收（最关键的一次）**：选小宇 → 做 q_001 → 照黄金脚本走 4 轮 → 看到状态从困惑到挫败、关怀被触发、画图出现、会话结束生成复习任务。**这一关过了，产品的核心就立住了。**

## 5. 阶段三 · 演示面（约 5 天）

**目标**：把「可解释」和「教师/家长价值」两个门面做出来。

### 任务卡

**T3-1（彭海）观察面板数据接口**
- 做什么：提供「一次会话的逐轮决策链路」数据——每轮的读取记忆、识别状态+证据、策略+原因、是否关怀、是否画图、写回数据、复习任务。
- 完成标准：给一个 session_id，返回结构化的决策链路数据。

**T3-2（葛泽桐）观察面板页 Observer**
- 做什么：把 T3-1 的数据按《MVP流程》§3 展示成「读了什么→判了什么→为什么切策略→写回了什么」。建议时间线/逐轮卡片。
- 完成标准：评委能一眼看懂某轮「为什么从 hint 切到 care+small_step」。
- 值得多打磨：这是「可解释」卖点的脸面，初版出来后两人多调几轮布局。

**T3-3（彭海）报告数据接口**
- 做什么：按《种子脚本》§4 第 7 步，聚合出教师视角、家长视角的摘要数据。
- 完成标准：返回薄弱点、错因、干预记录、复习建议（教师）；学习状态、完成情况、陪伴建议（家长）。

**T3-4（葛泽桐）报告预览页 Report**
- 做什么：教师/家长两个视角的展示页。
- 完成标准：两个视角的摘要都能看到，措辞贴近文档示例。

**T3-5（葛泽桐）多学生对比演示分支前端 + 自测脚本**
- 做什么：把小琳、小哲的对比演示分支（《种子脚本》§5）在前端跑通；写一个简单自测清单/脚本，覆盖三个学生的演示路径。
- 完成标准：能依次演示三个学生、看到系统对他们的不同反应；自测清单能逐项打勾。
- 价值：把「因材施教」的演示前端也交给葛泽桐，彭海只需保证后端接口给对数据。

## 6. 阶段四 · 收尾（约 5 天 + 缓冲）

**目标**：接真大模型、调到好用、视觉打磨、彩排。

### 任务卡

**T4-1（彭海）接真国内大模型**
- 做什么：在 `llmClient.js` 把 mock 换成真实 API（彭海选定的那家），按其真实请求/响应格式适配；保留 mock 开关兜底。
- 完成标准：`LLM_MODE=live` 时真联网，情绪识别和回应来自真模型；断网切 mock 不崩。
- 依赖：彭海需先选定模型家、拿到 API 文档和密钥（这件事可在阶段三就并行去办，别卡到最后）。

**T4-2（彭海）调提示词**
- 做什么：用真模型实测《人设规格》§3/§5 的提示词，迭代到「情绪判得准、灵灵说话像那么回事」。
- 完成标准：跑黄金脚本和反讽测试（「哦我可太会了」判挫败），效果可接受。

**T4-3（葛泽桐）全局 UI 打磨 + 演示文档**
- 做什么：① 统一配色、字体、间距、灵灵头像气泡，让四个页面适合路演；② 写 README（怎么启动）和一份「演示操作说明」（路演时点哪、说什么）。
- 完成标准：整体观感统一、不像半成品；照着 README 别人能把项目跑起来；演示说明能让彭海/葛泽桐照着走完整流程。

**T4-4（彭海+葛泽桐）演示彩排 + 抓 bug**
- 做什么：完整走一遍黄金路径 + 小琳/小哲对比分支 + 备用分支（安全响应、反讽），列 bug 清单逐个修。
- 完成标准：能在不翻车的情况下完整演示一遍。

**留 2~3 天缓冲**：吸收意外，别排满。

## 7. 待定决策清单（撞到再拍，先用最简实现）

这些先不定，用最简做法跑通，到了再说，避免阻塞：

| 决策项 | 先用的最简做法 | 何时再定 |
|---|---|---|
| 会话怎么算结束 | 学生点「完成本次学习」按钮触发复盘 | 阶段二，跑通后看顺不顺 |
| 掌握度增减公式 | 答对+8、答错-8，封顶[0,100] | 阶段二跑通后，想让曲线更真再加难度系数 |
| 几何图怎么画 | 先用预置 SVG 占位 | 若有余力，阶段四再考虑真渲染 |
| 前后端接口清单 | 边做边加，做到哪个接哪个 | 不单独定 |
| 用哪家国内大模型 | mock 阶段不需要；阶段三并行去选 | 阶段四接入前定 |

> 每撞到一个，当场拍板 + 在此表记一笔，谁都能查。

## 8. 葛泽桐的协作约定

- **只在自己的分支 + 自己的地盘干活**：所有改动在 `feature/` 分支，只动 `/web` 前端；§1.5「只读清单」里的文件碰都不碰，要改提给彭海。
- **类型不报错才算完**：前端调接口必须用彭海给的 TS 类型，编辑器飘红/编译不过就是没做完，不要绕过类型硬塞。
- **交付前自测**：对照任务卡「完成标准」逐条过，自己分支上跑得起来，再发起合并请求给彭海 review。
- **以 `/docs` 规格为准**：展示什么、字段叫什么、措辞怎么写，查规格文档。

## 9. 给彭海的把关清单

- 每阶段末，彭海亲自跑一遍「阶段验收」那条路径，不要只听汇报。
- 葛泽桐交来的活，对照「完成标准」收，不达标退回并说清差在哪。
- 核心三块（状态识别、编排器、记忆写回）自己写或至少逐行看 AI 写的，因为评委最可能在这里追问、出问题也最难查。
- 大模型选型和密钥，阶段三就并行去办，别拖到阶段四卡脖子。
- 演示脚本（黄金路径+三人对比）彭海要能脱稿讲——它是路演的剧本。
