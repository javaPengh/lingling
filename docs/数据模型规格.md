# 灵灵老师 V0.1 数据模型规格

> 本文件是《项目主规格.md》第 8 节「数据原则」的实施细则，也是约束 AI 开发不偏离核心闭环的底层契约。
> 所有模块（学生学习主界面、教学编排器、忆感模块、深图模块、系统观察面板、报告预览）读写数据时，
> **必须以本文件定义的实体、字段、枚举为唯一标准**，不得自行新增表、改字段名或更改取值范围。
> 如需扩展：先改本文件，再改代码。

---

## 0. 设计原则与关键决策

本规格遵循以下原则，关键决策附理由，便于评审与修改。

1. **结构化优先**：原始对话只是衍生物，结构化学习事件与学生画像才是核心资产。
2. **可解释**：每一次策略切换、每一次主动关怀触发，都必须能追溯到具体字段值，供系统观察面板展示。这是产品区别于普通聊天工具的关键，也是「假实现」最容易出现的地方。
3. **MVP 克制**：只定义跑通核心闭环必需的实体；不为想象中的未来功能预留复杂结构。
4. **AI 友好**：字段命名统一、枚举封闭、关系清晰，让 AI 难以用关键词匹配或写死数据来「假装」实现记忆与状态识别。

**已锁定的四个关键决策（如需调整，请在此表修改后通知我）：**

| 决策项 | 选定方案 | 理由 |
|---|---|---|
| 掌握度表示 | 底层存 `0-100` 整数，展示层映射四档 | 计算与趋势曲线需要数值；纯分数太「假精确」，故展示层降维成四档便于向评委解释 |
| 学习状态枚举 | 五类：`stable / confused / frustrated / tired / anxious` | 验收要求的三类只是下限；五类才能撑起「关注情绪」卖点，且每类对应不同策略，演示更丰富 |
| 错因记录 | 分类枚举 + 自由文本备注，二者都存 | 分类驱动机器决策与报告聚合；自由文本承载灵灵给学生的个性化反馈 |

> **关于存储**：本文件是**逻辑数据模型**，只定义「有哪些实体、哪些字段、什么类型、什么关系、什么读写契约」。
> 具体用哪种数据库（SQLite / 浏览器存储 / 文件 / 服务端库）、字段命名风格、主键生成方式等**物理实现细节，留待技术选型阶段确定**，届时单独出一份《数据访问层规格 / 建表脚本》。
> 第 6 节给出的 SQLite 建表语句仅是「参考实现之一」，不构成对存储方案的锁定。

## 1. 通用约定（逻辑层）

以下为**逻辑模型层面**的约定，与具体数据库无关。括号中的「物理实现示例」仅供参考，最终以技术选型后的《数据访问层规格》为准。

- **类型表示**：本文档统一用中立类型——`字符串 / 整数 / 布尔 / 时间 / JSON / 枚举`。映射到具体库时再转换（如布尔在 SQLite 用 0/1，在 JSON/JS 中用 true/false）。
- **标识**：每个实体有唯一标识 `id`（逻辑上的主键）。生成方式（UUID、自增、可读短码）选型时定；演示种子数据建议用可读短码（如 `stu_001`、`q_001`）便于调试。
- **命名**：字段名在本文档用 `snake_case` 表述以保持一致；落地时若框架习惯 camelCase，可整体转换，但**字段语义与集合必须与本文档一一对应，不得增删改名**。
- **时间**：所有时间字段用 ISO 8601、UTC，例 `2026-05-21T08:30:00Z`。
- **JSON 字段**：复杂结构（数组、对象）逻辑上是 JSON；物理上可存为 JSON 字符串或拆成关联表，本文档对每个 JSON 字段给出结构示例。
- **枚举**：枚举值一律用小写英文短码（便于代码判断）；中文展示文案由前端映射表负责，**不进入数据层**。
- **关系**：实体间引用用 `<引用实体>_id` 表述（如 `student_id`）；是否建物理外键约束选型时定，但逻辑关系不可省略。
- **可空**：除特别说明，标识与核心字段必填；「分析结果类」字段允许为空，表示「尚未分析」。

## 2. 枚举字典（全局唯一来源）

所有模块共用以下枚举。前端中文展示文案在此一并给出，代码中不得硬编码其它取值。

### 2.1 学习状态 `learning_state`

| 短码 | 中文展示 | 含义 | 典型信号（写入 state_evidence） |
|---|---|---|---|
| `stable` | 平稳 | 正常作答，节奏稳定 | 答对、正常追问、无负面表达 |
| `confused` | 困惑 | 卡在某步但仍在尝试 | 反复修改、问「这步怎么来的」、长时间停顿 |
| `frustrated` | 挫败 | 连续受挫，出现放弃倾向 | 连续答错、「我不会」「算了」、情绪化表达 |
| `tired` | 疲惫 | 注意力下降，效率走低 | 会话偏长、答题变慢、敷衍式回复 |
| `anxious` | 紧张/焦虑 | 担心做不好、怕考试 | 「来不及了」「会不会考」「我是不是很差」 |

> 状态识别结果与其证据必须成对写入 `learning_event.state` 与 `learning_event.state_evidence`，否则视为假实现。

### 2.2 教学策略 `teaching_strategy`

| 短码 | 中文展示 | 描述 |
|---|---|---|
| `socratic` | 苏格拉底追问 | 默认策略，用提问引导学生自己推理，不直接给答案 |
| `small_step` | 拆小步引导 | 把解题路径拆到最小粒度，一步一确认 |
| `hint` | 关键提示 | 给方向性提示而非完整步骤 |
| `care` | 主动关怀 | 先处理情绪再处理题目：降压、共情、鼓励 |
| `humor` | 幽默调节 | 轻度幽默/类比降低紧张，须服务教学不喧宾夺主 |
| `direct_explain` | 直接讲解 | 仅在多次启发无效或学生明确放弃时兜底使用 |

> 一次教学回应可组合多个策略（如 `["care","small_step"]`），故在事件表中以 JSON 数组存储。

### 2.3 错因分类 `error_cause`

| 短码 | 中文展示 | 说明 |
|---|---|---|
| `calculation` | 计算错误 | 运算、移项、符号等机械性失误 |
| `concept` | 概念不清 | 对定义、定理、性质理解有误 |
| `misread` | 审题失误 | 看错条件、漏看信息、误解题意 |
| `method` | 方法选择不当 | 思路方向错或选了低效/错误方法 |
| `incomplete` | 步骤缺失 | 思路对但漏关键步骤或讨论不全 |
| `careless` | 粗心 | 抄错、笔误等非能力性失误 |
| `unknown` | 暂未归因 | 尚未分析或无法归类 |

> 机器决策与报告聚合用本分类；本题专属的个性化说明写入自由文本字段 `error_detail`。

### 2.4 掌握度档位（展示层映射，不入库）

| 分数区间 | 展示档位 |
|---|---|
| 0–40 | 未掌握 |
| 41–60 | 薄弱 |
| 61–85 | 基本掌握 |
| 86–100 | 熟练 |

### 2.5 题目难度 `difficulty`

`easy / medium / hard` 三档。

### 2.6 复习任务状态 `review_status`

`pending（待复习） / done（已完成） / skipped（已跳过）`。

### 2.7 视觉辅助类型 `visual_aid_type`（深图/画图模块用）

| 短码 | 中文展示 | 说明 |
|---|---|---|
| `none` | 无 | 本轮不需要画图 |
| `function_graph` | 函数图像 | 坐标系中绘制函数曲线 |
| `geometry` | 几何图形 | 平面/立体几何示意 |
| `annotation` | 标注高亮 | 在已有图/题上做高亮、辅助线、标注 |
| `diagram` | 示意图 | 流程、关系、概念示意 |

## 3. 实体总览与关系

九张核心表，覆盖主规格第 8 节要求沉淀的全部数据项。

```text
student（学生）
  ├─ student_profile（学生画像，1:1，长期记忆主体）
  ├─ student_knowledge（学生×知识点 掌握度，N:1 到 knowledge_point）
  └─ session（学习会话）
        └─ learning_event（学习事件，核心资产，闭环每一轮产出一条）
                 └─ 引用 question

question（题目） ─< question_knowledge >─ knowledge_point（知识点）   ← 多对多

review_task（复习任务） ── 关联 student / knowledge_point / 触发它的 learning_event
```

实体职责对照主规格模块：

- `student_profile` + `student_knowledge` = **忆感模块**的长期记忆载体。
- `question` + `knowledge_point` + `learning_event` 的错因字段 = **深图模块**的分析对象与产出。
- `learning_event` 的状态/策略/关怀字段 = **教学编排器**的决策记录（也是观察面板的数据源）。
- `review_task` = 闭环末端的**主动复习任务**。

## 4. 实体字段定义

### 4.1 student（学生）

最小身份信息，配合主规格「统一登录」。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | 字符串 | 标识 | 学生 ID |
| name | 字符串 | 必填 | 姓名/昵称 |
| grade | 字符串 | 必填 | 年级，如 `高一` |
| created_at | 字符串 | 必填 | 创建时间 |

### 4.2 student_profile（学生画像 · 长期记忆主体）

与 student 1:1。承载「永久记忆」中**跨会话稳定的画像**，每次学习结束后被更新。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | 字符串 | 标识 | |
| student_id | 字符串 | 引用 student, 唯一 | |
| weak_points | JSON | | 薄弱知识点 id 数组，例 `["kp_003","kp_007"]`，由 student_knowledge 低分项汇总 |
| recent_states | JSON | | 最近 N 次学习的主导状态数组，例 `["frustrated","confused","stable"]`，供忆感判断趋势 |
| effective_strategies | JSON | | 历史上对该生有效的策略短码数组，例 `["small_step","humor"]` |
| learning_summary | 字符串 | | 自然语言长期画像摘要，供灵灵 prompt 注入与报告引用 |
| total_sessions | 整数 | 必填, 默认0 | 累计会话数 |
| updated_at | 字符串 | 必填 | 最近更新时间 |

### 4.3 knowledge_point（知识点）

预置的高中数学知识点字典，是深图模块标注题目、报告聚合薄弱点的基础。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | 字符串 | 标识 | 知识点 ID |
| name | 字符串 | 必填 | 知识点名称，如 `二次函数最值` |
| subject | 字符串 | 必填 | 学科，V0.1 固定 `math` |
| chapter | 字符串 | | 所属章节，如 `函数` |
| parent_id | 字符串 | 引用 knowledge_point, 可空 | 上位知识点 id，支持简单层级（无则为顶层） |

### 4.4 student_knowledge（学生 × 知识点掌握度）

长期记忆的**量化部分**，每个学生对每个接触过的知识点一条记录。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | 字符串 | 标识 | |
| student_id | 字符串 | 引用 student | |
| knowledge_point_id | 字符串 | 引用 knowledge_point | |
| mastery | 整数 | 必填, 0–100 | 掌握度分数，展示时映射 §2.4 四档 |
| attempts | 整数 | 必填, 默认0 | 该知识点累计作答次数 |
| correct_count | 整数 | 必填, 默认0 | 累计答对次数 |
| last_practiced_at | 字符串 | | 最近练习时间 |

> 约束：`(student_id, knowledge_point_id)` 唯一。

### 4.5 question（题目）

预置种子题库。V0.1 以高中数学错题为验证场景。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | 字符串 | 标识 | 题目 ID |
| stem | 字符串 | 必填 | 题干（支持基础数学符号/LaTeX 文本） |
| standard_answer | 字符串 | 必填 | 标准答案 |
| solution | 字符串 | 必填 | 标准解题步骤（供深图模块对照、灵灵兜底讲解） |
| difficulty | 字符串 | 必填 | 见 §2.5 |
| typical_errors | JSON | | 本题典型错因数组，例 `[{"cause":"concept","detail":"忘记判别式≥0"}]`，供深图快速归因 |
| visual_aid_type | 字符串 | 必填, 默认'none' | 本题建议的画图类型，见 §2.7 |
| visual_aid_spec | JSON | | 画图参数（如函数表达式、坐标范围、几何点坐标），结构由画图模块约定，可空 |

### 4.6 question_knowledge（题目 × 知识点 关联表）

题目与知识点多对多。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | 字符串 | 标识 | |
| question_id | 字符串 | 引用 question | |
| knowledge_point_id | 字符串 | 引用 knowledge_point | |

> 约束：`(question_id, knowledge_point_id)` 唯一。

### 4.7 session（学习会话）

一次「进入今日任务到本次复盘」的完整学习过程。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | 字符串 | 标识 | 会话 ID |
| student_id | 字符串 | 引用 student | |
| started_at | 字符串 | 必填 | 开始时间 |
| ended_at | 字符串 | | 结束时间，进行中为 NULL |
| dominant_state | 字符串 | | 本次会话主导学习状态（见 §2.1），复盘时由事件聚合得出 |
| summary | 字符串 | | 本次学习复盘文本（学生可读），复盘时生成 |
| event_count | 整数 | 必填, 默认0 | 本会话学习事件数 |

### 4.8 learning_event（学习事件 · 核心资产）

**整个产品最重要的表**。闭环每一轮交互产出一条，承载状态识别、策略决策、关怀触发、画图调用、错因归因的完整记录。系统观察面板基本就是这张表的可视化。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | 字符串 | 标识 | 事件 ID |
| session_id | 字符串 | 引用 session | |
| student_id | 字符串 | 引用 student | 冗余存储，便于按学生跨会话查询 |
| question_id | 字符串 | 引用 question, 可空 | 本轮关联题目；若为自由提问可空 |
| sequence | 整数 | 必填 | 本会话内的轮次序号，从 1 递增 |
| student_input | 字符串 | | 学生本轮输入（题目作答/追问/困惑表达）原文 |
| student_answer | 字符串 | | 若本轮是作答，记录答案；非作答轮为 NULL |
| is_correct | 布尔 | 可空 | 作答是否正确；非作答轮为空 |
| knowledge_point_ids | JSON | | 深图识别出的本轮命中知识点 id 数组 |
| error_cause | 字符串 | 可空 | 错因分类，见 §2.3；答对或无错为 NULL |
| error_detail | 字符串 | 可空 | 错因自由文本说明（个性化） |
| state | 字符串 | 必填 | 本轮识别出的学习状态，见 §2.1 |
| state_evidence | 字符串 | 必填 | 状态识别依据（信号原文/规则），观察面板展示用，**不可省略** |
| strategy | JSON | 必填 | 本轮采用的教学策略数组，见 §2.2 |
| strategy_reason | 字符串 | 必填 | 选择/切换该策略的原因，观察面板展示用，**不可省略** |
| care_triggered | 布尔 | 必填, 默认 false | 是否触发主动关怀 |
| visual_aid_used | 字符串 | 必填, 默认'none' | 本轮实际使用的画图类型，见 §2.7 |
| tutor_response | 字符串 | 必填 | 灵灵本轮输出的教学回应原文 |
| created_at | 字符串 | 必填 | 事件时间 |

> **设计要点**：`state_evidence`、`strategy_reason`、`care_triggered` 三个字段是「可解释性」的命脉。AI 若把它们填成空字符串或套话，即未满足验收第 13、14 条。代码评审应重点检查这三个字段是否由真实逻辑产生。

### 4.9 review_task（复习任务）

闭环末端产出的**主动复习任务**，对应验收「生成至少一个主动复习任务」。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | 字符串 | 标识 | |
| student_id | 字符串 | 引用 student | |
| knowledge_point_id | 字符串 | 引用 knowledge_point | 针对的薄弱知识点 |
| source_event_id | 字符串 | 引用 learning_event, 可空 | 触发本任务的学习事件，体现「为什么布置」 |
| reason | 字符串 | 必填 | 生成原因（如「本次该知识点连错 2 题，掌握度降至 38」），报告/观察面板展示用 |
| recommended_question_id | 字符串 | 引用 question, 可空 | 推荐复习题 |
| status | 字符串 | 必填, 默认'pending' | 见 §2.6 |
| due_date | 字符串 | | 建议复习日期 |
| created_at | 字符串 | 必填 | |

### 4.10 account（账号 · 三角色登录）

> 新增。支撑产品的**三角色结构**（学生/家长/老师）。MVP 不做真实鉴权（无密码、无 token），
> 只用最小的"账号"概念表达"谁、什么角色、关联哪个学生"，由登录入口（预置账号选择）使用。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | 字符串 | 标识 | 账号 ID |
| role | 字符串 | 必填 | 角色枚举：`student` / `parent` / `teacher` |
| display_name | 字符串 | 必填 | 登录入口展示的名字，如「小宇」「小宇的家长」「王老师」 |
| student_id | 字符串 | 引用 student, 可空 | 仅 role=student 时有值：该账号对应的学生本人 |
| created_at | 字符串 | 必填 | |

> - `role=student`：`student_id` 指向其本人的 student 实体。
> - `role=parent`：关联的孩子通过 §4.11 teacher_student 之外的方式——家长用同一张关联表（见下），或简化为家长账号也走 §4.11 的关联（parent 关联其孩子）。
> - `role=teacher`：通过 §4.11 关联其所带的多个学生。

### 4.11 account_student（账号 × 学生 关联 · 家长/老师看谁）

> 新增。表达"家长/老师账号能查看哪些学生"。家长通常关联一个孩子，老师关联多个。学生账号本人不用此表（用 account.student_id 即可）。

## 5. 长期记忆「读—写回」契约（关键流程）

「永久记忆」最容易被做成假功能，故此处把字段级回路固定下来。AI 必须严格按此实现。

### 5.1 会话开始 · 读取（忆感模块 → 教学编排器）

进入今日任务时，按 `student_id` 读取并注入编排器上下文：

1. `student_profile`：`weak_points`、`recent_states`、`effective_strategies`、`learning_summary`。
2. `student_knowledge`：该生 mastery < 60 的知识点列表（薄弱点）。
3. 最近 1–2 个 `session` 的 `dominant_state` 与 `summary`。

→ 这些数据共同决定灵灵的开场语气、起始策略与重点关注的知识点。观察面板「读取到的历史记忆」展示的就是这一步的结果。

### 5.2 每轮交互 · 写入（教学编排器 → learning_event）

每轮交互结束，写入一条 `learning_event`，**九个决策字段必须由真实逻辑产生**：
`state`、`state_evidence`、`error_cause`、`error_detail`、`strategy`、`strategy_reason`、`care_triggered`、`visual_aid_used`、`knowledge_point_ids`。

### 5.3 会话结束 · 写回（复盘逻辑 → 长期记忆）

本次学习结束时执行：

1. 更新 `student_knowledge`：对本会话涉及的每个知识点，按答对/答错调整 `mastery`、累加 `attempts`/`correct_count`、更新 `last_practiced_at`。
   - 建议规则（可调）：答对 `+5~+10`、答错 `-5~-10`，封顶 [0,100]。
2. 更新 `student_profile`：重算 `weak_points`、追加本次主导状态到 `recent_states`、若某策略明显有效则并入 `effective_strategies`、重写 `learning_summary`、`total_sessions += 1`。
3. 回填 `session`：`ended_at`、`dominant_state`、`summary`、`event_count`。
4. 生成 `review_task`：对本次掌握度下降或连续答错的薄弱知识点，至少生成一条，并填好 `reason` 与 `source_event_id`。

→ 观察面板「写回的结构化数据」「生成的主动复习任务」展示的就是这一步。

## 6. 附录：SQLite 参考实现（仅为示例之一，不构成存储方案锁定）

> 下面这份 SQLite 建表语句**只是把第 4 节逻辑模型落地的一种可能方式**，用来帮助理解字段如何映射到真实存储。
> **它不是技术选型决定**。技术选型阶段若选择其它方案（浏览器存储 / 文件 / 服务端数据库 / ORM），应据第 4 节逻辑模型另行产出对应的建表脚本或 Schema。
> 字段定义的权威是第 2~4 节，不是这段 SQL。

```sql
PRAGMA foreign_keys = ON;


CREATE TABLE student (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL,
  grade       TEXT NOT NULL,
  created_at  TEXT NOT NULL
);

CREATE TABLE student_profile (
  id                    TEXT PRIMARY KEY,
  student_id            TEXT NOT NULL UNIQUE,
  weak_points           TEXT,
  recent_states         TEXT,
  effective_strategies  TEXT,
  learning_summary      TEXT,
  total_sessions        INTEGER NOT NULL DEFAULT 0,
  updated_at            TEXT NOT NULL,
  FOREIGN KEY (student_id) REFERENCES student(id)
);

CREATE TABLE knowledge_point (
  id         TEXT PRIMARY KEY,
  name       TEXT NOT NULL,
  subject    TEXT NOT NULL,
  chapter    TEXT,
  parent_id  TEXT,
  FOREIGN KEY (parent_id) REFERENCES knowledge_point(id)
);

CREATE TABLE student_knowledge (
  id                  TEXT PRIMARY KEY,
  student_id          TEXT NOT NULL,
  knowledge_point_id  TEXT NOT NULL,
  mastery             INTEGER NOT NULL CHECK (mastery BETWEEN 0 AND 100),
  attempts            INTEGER NOT NULL DEFAULT 0,
  correct_count       INTEGER NOT NULL DEFAULT 0,
  last_practiced_at   TEXT,
  UNIQUE (student_id, knowledge_point_id),
  FOREIGN KEY (student_id) REFERENCES student(id),
  FOREIGN KEY (knowledge_point_id) REFERENCES knowledge_point(id)
);

CREATE TABLE question (
  id               TEXT PRIMARY KEY,
  stem             TEXT NOT NULL,
  standard_answer  TEXT NOT NULL,
  solution         TEXT NOT NULL,
  difficulty       TEXT NOT NULL CHECK (difficulty IN ('easy','medium','hard')),
  typical_errors   TEXT,
  visual_aid_type  TEXT NOT NULL DEFAULT 'none',
  visual_aid_spec  TEXT
);

CREATE TABLE question_knowledge (
  id                  TEXT PRIMARY KEY,
  question_id         TEXT NOT NULL,
  knowledge_point_id  TEXT NOT NULL,
  UNIQUE (question_id, knowledge_point_id),
  FOREIGN KEY (question_id) REFERENCES question(id),
  FOREIGN KEY (knowledge_point_id) REFERENCES knowledge_point(id)
);

CREATE TABLE session (
  id              TEXT PRIMARY KEY,
  student_id      TEXT NOT NULL,
  started_at      TEXT NOT NULL,
  ended_at        TEXT,
  dominant_state  TEXT,
  summary         TEXT,
  event_count     INTEGER NOT NULL DEFAULT 0,
  FOREIGN KEY (student_id) REFERENCES student(id)
);

CREATE TABLE learning_event (
  id                   TEXT PRIMARY KEY,
  session_id           TEXT NOT NULL,
  student_id           TEXT NOT NULL,
  question_id          TEXT,
  sequence             INTEGER NOT NULL,
  student_input        TEXT,
  student_answer       TEXT,
  is_correct           INTEGER,
  knowledge_point_ids  TEXT,
  error_cause          TEXT CHECK (error_cause IN
                         ('calculation','concept','misread','method',
                          'incomplete','careless','unknown') OR error_cause IS NULL),
  error_detail         TEXT,
  state                TEXT NOT NULL CHECK (state IN
                         ('stable','confused','frustrated','tired','anxious')),
  state_evidence       TEXT NOT NULL,
  strategy             TEXT NOT NULL,
  strategy_reason      TEXT NOT NULL,
  care_triggered       INTEGER NOT NULL DEFAULT 0,
  visual_aid_used      TEXT NOT NULL DEFAULT 'none',
  tutor_response       TEXT NOT NULL,
  created_at           TEXT NOT NULL,
  FOREIGN KEY (session_id) REFERENCES session(id),
  FOREIGN KEY (student_id) REFERENCES student(id),
  FOREIGN KEY (question_id) REFERENCES question(id)
);

CREATE TABLE review_task (
  id                      TEXT PRIMARY KEY,
  student_id              TEXT NOT NULL,
  knowledge_point_id      TEXT NOT NULL,
  source_event_id         TEXT,
  reason                  TEXT NOT NULL,
  recommended_question_id TEXT,
  status                  TEXT NOT NULL DEFAULT 'pending'
                            CHECK (status IN ('pending','done','skipped')),
  due_date                TEXT,
  created_at              TEXT NOT NULL,
  FOREIGN KEY (student_id) REFERENCES student(id),
  FOREIGN KEY (knowledge_point_id) REFERENCES knowledge_point(id),
  FOREIGN KEY (source_event_id) REFERENCES learning_event(id),
  FOREIGN KEY (recommended_question_id) REFERENCES question(id)
);
```

## 7. 演示种子数据约定

为保证可演示、可复现，初始化时须预置以下最小种子数据（具体内容建议单独出一份《种子数据与演示脚本》）：

- **1 名预置学生**（含 `student_profile`，带 1–2 个已知薄弱点与负面 `recent_states`，便于演示「读取历史记忆」）。
- **6–10 个知识点**，覆盖至少 2 个章节。
- **5–8 道种子题**，每题挂载 1–2 个知识点、填好 `typical_errors`，其中至少 1 道带 `visual_aid_type`（用于演示画图能力）。
- **预置 student_knowledge**：让该生对薄弱知识点 mastery 落在 41–60（薄弱档），制造「需要被关注」的初始态势。

> 种子数据应能让一条完整演示路径自然触发：平稳 → 答错进入困惑 → 再错进入挫败 → 触发主动关怀+幽默+拆小步 → 调用画图 → 复盘写回 → 掌握度下降 → 生成复习任务。这条路径同时就是参赛演示脚本。
